# 格式与兼容性

## HDR 与颜色

默认采用 preserve 路径：主图可重压缩、缩放或换格式，增益图不因质量预设被缩小或重新生成。严格模式保留增益图解码样本与解释参数；超过支持精度或无法承载时拒绝转换，不静默降为 SDR。

HEIC / AVIF 新任务默认开启各自的相册兼容选项。彩色增益图转换为 BT.601 限定域 YCbCr：HEIC 采用 4:2:0，AVIF 采用 4:4:4 再无损编码。存在色彩转换、采样或舍入误差，**不承诺 RGB 逐值无损**；增益图尺寸和 HDR 参数保留。单通道保留原始灰度值。关闭兼容选项可保留严格 GBR，但部分查看器会偏色或不识别 HDR。

大 HEIC/AVIF 使用分块容器以避开系统解码限制，保留原分辨率。奇数尺寸 HDR AVIF 采用 AOM 4:4:4；纯 SDR 主图使用 SVT-AV1 4:2:0。奇数尺寸 SDR 分块的编码画布补齐为偶数，通过 clean aperture 保持原始可见尺寸，不缩放或裁掉源像素。该 SDR 路径已在 Android 15/16 模拟器通过平台解码；仍须在目标真机相册验收。HDR 的例外路径可能更慢。

当前编码输出为 8 位；HEIC/AVIF HDR 转 JPEG 无法满足保留条件时会拒绝。JXL 的系统相册支持因平台不同而变化。

## 校验与预览

- API 34+ 保存兼容 HDR HEIC/AVIF 前检查本机系统能否读出主图和增益图。
- SDR 在 API 29+ 且系统声明支持目标 MIME 时先做平台解码校验；不支持的格式不以平台解码失败判断其文件无效。
- 纯 SDR HEIF 文件不应带没有对应 tone-map item 的 `tmap` brand。
- 应用预览有原生解码兜底，比较视图显示 SDR 主图。应用内可见不等于外部相册能识别 HDR；外部显示还取决于系统、软件和屏幕。

## 系统版本

Android 8/9 可转换并通过分享导出，尚未实现直接保存相册。直接入册需 Android 10+；系统回收站与校验后替换需 Android 11+。格式可转换不代表该系统或所有相册支持显示。

## 原图、动态照片与后台

默认保留原图。自动替换须主动启用；只处理通过校验、完整保存且更小的成品，保存回原相册后，在首页主动点击待替换卡片发起系统回收确认；大批量每批都需点击，不会后台连续弹窗。回收站期限由系统决定。试转不自动替换。

支持检测并按容器能力携带动态视频；Android Motion Photo 与 Apple Live Photo 不是同一种配对方式。Apple 导出 ZIP 是传输包，须由 [Mac 配套工具](../apple-live/README.md)完成配对和 PhotoKit 导入。

转换不要求始终停留在界面，但系统强制停止、厂商进程清理、温控和前台服务时限仍可能中断。新任务使用直接前台服务，规避 WorkManager 在 Android 16 的作业配额问题；这不等于无限后台运行。详见 [后台修复与验证](reports/2026-10-12-background-conversion.md)。

## 性能表述

当前使用 CPU 多线程和按 CPU 能力分派的 SIMD 优化；没有接入 MediaCodec/GPU 硬件编码。代码中存在 SVE/SVE2 不代表每张图片都会走该路径。`docs/design/` 中的硬件编码内容是设计草案，不能当作已实现功能。
