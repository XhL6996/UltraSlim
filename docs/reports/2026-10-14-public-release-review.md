# 2026-10-14 首次公开发行审查

后续处理：已在 1.1.10 落地修复，当前进展与验收范围见 [修复报告](2026-10-14-public-release-fixes.md)。下文保留修复前的审查证据。

## 结论

**不建议把当前工作区直接作为首个公开稳定安装版。** 源码结构、GPLv3 声明、依赖来源、构建说明已具备开放基础，核心构建与多数回归通过；但发布前应先修复保存恢复误认同名文件的问题。解决该项、明确 AVIF 平台限制、修复测试入口并准备正式发行材料后，适合作为首个公开测试版。

审查对象为 `0104990` 加当前全部工作区改动（应用版本 `1.1.9` / `21`），包括 2026-10-14 的预览、统计、队列和删除协调优化。以下功能问题是当前版本存在的问题，不将其归因于本轮优化：同名恢复逻辑和奇数尺寸 AVIF 编码分支在本轮之前已经存在。

本轮未修改业务代码、提交、推送或覆盖手机上的应用。为诊断临时添加测试，并临时调整一次队列测试等待；结束后均恢复。只新增本报告。本次新运行的设备验证均为模拟器；当前连接手机是另一台测试机，不是此前的 ColorOS 手机。

## 发布前需处理的发现

### P1：不能只凭同名文件认定保存成功并删除私有成品

位置：`app/src/main/java/app/ultraslim/convert/MediaStoreSaver.kt:94-102`，以及 `OutputStore.kt:41-44`。

恢复发布时，代码按 `DISPLAY_NAME + RELATIVE_PATH` 查询，发现非 pending 项就直接返回 URI，没有验证该文件内容与本次待保存成品一致。`OutputStore.save` 随即把记录标成 SAVED 并删除应用内成品。

复现：创建有效待保存 JPEG，再在目标相册创建名字与恢复查询一致、但像素和尺寸不同的 JPEG，调用实际 `OutputStore.save`。Android 15 / 16 模拟器均记录：

```text
collision reused=true privateExists=false bytesMatch=false
```

最终独立断言确认保存后文件的 SHA-256 与正确成品不同。原图未删除，但唯一的正确转换成品已被丢弃，历史记录却指向另一张图。触发场景包括同名冲突，以及发布中断后、重试前相册文件被其他软件改写。

建议：恢复认领前验证内容一致性及可读性，冲突时使用新名称保存；只有确认相册中的文件与私有成品一致后才删除私有副本。添加“同名异内容”和“中断恢复期间成品变化”的回归。仅依赖自动替换的后续 hash 检查不足以保护已被删除的私有成品。

### P2：奇数尺寸 SDR AVIF 的 AOM 4:4:4 分块路径仍有平台兼容缺口

位置：`native/jni/transcode.cpp:1502-1519`；现有测试 `SdrOutputCompatibilityTest.kt:49`。

相同 APK、相同生成流程，分别做保存前采样解码和全尺寸 `ImageDecoder` 解码：

| SDR 图片尺寸 | Android 15 模拟器 | Android 16 模拟器 |
| --- | --- | --- |
| 513 × 385 | 两种解码均通过 | 两种解码均通过 |
| 5001 × 513 | 两种解码均通过 | 两种解码均失败 |
| 513 × 5001 | 两种解码均通过 | 两种解码均失败 |
| 5002 × 513 | 两种解码均通过 | 两种解码均失败 |
| 5002 × 514 | 两种解码均通过 | 两种解码均通过 |

失败是 `java.io.IOException: getPixels failed with error invalid input`。Android 16 镜像指纹为 `google/sdk_gphone64_arm64/emu64a:16/BE2A.250530.026.F3/13894323:userdebug/dev-keys`。不据此宣称所有 Android 16 真机失败，也不据此认定 AVIF 文件封装必然不合规。

现有 `SdrOutputValidation` 会拒绝发布、保留原图，这是有效保护；用户仍会遇到默认 AVIF 转换失败。稳定版前应解决该路径，或明确限制与改用 JPEG 的提示，并在目标系统/设备上复验。不能靠关闭平台校验、静默裁剪或缩小照片来使测试通过。

### P2：公开设备验证入口与新测试的包名守卫冲突

`scripts/verify.sh:15-16` 和 BUILDING 文档使用 `.verifyqa`；新增 `HistoryDeletionCoordinationTest.kt:17` 却硬性要求包名以 `.optqa` 结尾。因此公开文档中的 `scripts/verify.sh --device` 在执行该测试时必然失败，默认 `.debug` 同样失败。

建议统一隔离测试包约定，保留防止误测日常数据的保护。该问题由源码条件即可确定；本轮设备测试使用 `.optqa`，没有把其通过当作标准脚本已通过。

### P2：队列动画回归存在采样等待竞态

`QueueActionsUiTest.kt:70-84` 更新 CONVERTING 后等待“已处理 0 / 6 张”，该文案可能在队列变化之前就存在。Compose 手动时钟前进不等于 HomeViewModel 的真实 `Flow.sample(150)` 时间已经过去，因此立即断言置顶顺序会失败。

原测试在 Android 16 完整套件和独立复跑均失败。诊断时仅在测试更新状态之后增加 500 ms 的真实等待，同一业务 APK 的置顶、波浪动画帧变化、进度与队列顺序全部通过。该临时等待已撤销；建议正式测试等待转换中节点/状态实际呈现，不用固定 sleep。此结果不支持把失败解释为“转换动画仍然没有实现”。

## 发行材料尚未完成

- Release 当前产物是 `app-release-unsigned.apk`，没有正式发行签名配置。稳定保管的发行密钥、签名后校验和覆盖升级验收应在公开 APK 前完成。本轮测试签名使用开发证书，仅用于模拟器，不是发行密钥。
- 当前有 25 个已跟踪文件修改、20 个未跟踪文件（本报告加入前），包括 `ImageWork`、`ConversionBudget`、`HistoryRepository` 等必需源码。需完整提交/打 tag，避免只推送已跟踪的改动；还需在干净检出上确认源码与包对应。本轮复用了现有原生依赖，不宣称已完成从零下载的干净构建。
- GPLv3 与原生依赖许可快照在仓库内，但当前 APK 没有完整原生许可集/用户可读的开源声明；部分 AndroidX 许可仍保留在 META-INF，并非所有许可都被剥除。发布时应提供与二进制一起交付的完整告知和准确对应源码。`THIRD_PARTY_NOTICES.md` / `docs/RELEASING.md` 也明确说明当前清单不覆盖所有 Gradle 传递依赖。二进制告知要求见 [libjxl 固定版本许可](https://github.com/libjxl/libjxl/blob/v0.11.1/LICENSE)，Apache 许可与 NOTICE 交付要求见 [Apache-2.0 第 4 节](https://www.apache.org/licenses/LICENSE-2.0)。这不等同于完整许可证/专利法律审查。
- README / COMPATIBILITY 中“自动替换”的描述还没有准确说明现在每批都需要首页主动确认。Android 8/9 无直接相册保存实现（MediaStoreSaver 明确返回 null），公开兼容表应区分可转换/导出与可保存相册。
- 最新优化还缺真实大批量、低内存和 ColorOS 相机相册的完整发行验收；不能用模拟器回归或旧版本手机结果替代。
